### Second-cycle coding (Saldaña)
What it is:      a second pass that reorganises first-cycle codes into fewer, bigger, more abstract groupings.
Why it works:    first-cycle codes are many and close to the words; a second pass shows what keeps recurring.
When it fails:   forcing codes into categories too early, before every participant has been coded.
Advances mine:   the same move my dissertation needs: from single reviewer judgments to the pattern behind them.
Say:             "My first cycle gave me many codes per question; second cycle is where I find which ones repeat across people."
Ask:             "Do we finish first-cycle coding of all three interviews before any second-cycle grouping?"

### Pattern Coding (Saldaña)
What it is:      grouping similar codes into a smaller set of explanatory "meta-codes" (themes, causes, relationships).
Why it works:    it looks for what the codes have in common, a shared explanation, not just a shared topic.
When it fails:   when a pattern rests on one vivid participant; it needs support across cases.
Advances mine:   "AI agreement ends checking" would be a pattern code across auditor interviews, not one person's story.
Say:             "A pattern needs at least two codes across at least two participants, so a single vivid quote is a lead, not a theme."
Ask:             "When a pattern appears in two of three participants, do we report it as a theme or as a pattern still to test?"

### Focused Coding (Saldaña)
What it is:      selecting the most frequent or most significant codes to build the main categories.
Why it works:    it forces choices; not every code earns a place in the findings.
When it fails:   if frequency is mistaken for importance; one powerful In Vivo code can matter more than five routine ones.
Advances mine:   frequency vs. significance is the same trap as counting audit findings instead of weighing them.
Say:             "I'm using frequency as a starting point, not as proof of importance."
Ask:             "How do we justify keeping a code that appears once but matters a lot?"

### Axial Coding (Saldaña)
What it is:      relating categories to sub-categories by properties and dimensions (conditions, actions, consequences).
Why it works:    it turns a list of categories into a structure that says how they connect.
When it fails:   when it becomes theory-building before the data supports it.
Advances mine:   anchor (condition) → confirm (action) → converge (consequence) is an axial structure I could test.
Say:             "Axial coding is where categories start to explain each other instead of sitting side by side."
Ask:             "For a project this size, is axial coding expected, or is pattern coding enough?"

### Codes → categories → themes (Saldaña)
What it is:      a code labels a passage; a category groups codes; a theme is a phrase or sentence that says what a category means.
Why it works:    themes are written as statements ("Being an outsider is negotiated, not fixed"), not as labels.
When it fails:   when a "theme" is only a topic word, like "Water", rather than a claim about meaning.
Advances mine:   my research themes must be claims about judgment, not topic labels like "AI tools".
Say:             "I'm trying to write each theme as a sentence that makes a claim, not just a topic name."
Ask:             "Should our themes be phrased as sentences for the residency presentation?"

### The data analysis spiral (Creswell & Poth)
What it is:      analysis loops through managing data, reading and memoing, describing and classifying codes into themes, interpreting, and representing.
Why it works:    it is iterative; you return to the data as categories form, rather than moving in a straight line.
When it fails:   skipping memos, so the reasoning behind each grouping is lost.
Advances mine:   memoing my grouping decisions builds the audit trail my committee will expect.
Say:             "I'll write a short memo for each category explaining why those codes belong together."
Ask:             "Do you want analytic memos included with the Project 2 draft, or kept in NVivo only?"

### Links across readings
- Second-cycle methods (pattern, focused, axial) are different ways to climb from codes to themes.
- The two-codes, two-participants rule is a guard against themes built on one vivid quote.
- Creswell & Poth's spiral says to memo every grouping decision, which also guards that rule.
